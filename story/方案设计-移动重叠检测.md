# 方案设计文档 — 移动重叠检测 + 实时视觉反馈

## 1. 需求概述

**目标**：用户拖拽移动事件条时，实时检测目标位置是否与已有事件重叠。重叠则预览条变红 + 松手弹回，不产生错误数据。不重叠则正常放置。

**范围**：
- ✅ 移动(move)事件重叠检测（新增/拉伸已实现）
- ✅ mousemove 实时反馈（红/蓝色视觉区分）
- ✅ 背景事件(isBackground)不参与重叠计算
- ✅ 自身排除（不跟自己比）
- ❌ 不改变框选/拉伸逻辑
- ❌ 不改变 onEventDrop 回调签名

## 3. 架构设计

```
┌──────────────────────────────────────────────────────────┐
│ TimeCalendar.jsx（展示层编排）                             │
│ 消费 moveDragState.isOverlapping → EventBar prop          │
├──────────────────────────────────────────────────────────┤
│ EventBar.jsx（渲染 + DOM 标记）                           │
│ data-event-id="..."  data-is-background="true/false"      │
│ isOverlapping=true → 红色样式                              │
├──────────────────────────────────────────────────────────┤
│ useDragMove.js（交互编排）                                 │
│ mousemove: scanColumnOverlap → dragState.isOverlapping    │
│ mouseup:   isOverlapping? → reject : onEventDrop          │
├──────────────────────────────────────────────────────────┤
│ overlapScanner.js（纯扫描，零依赖）                        │
│ scanColumnOverlap(resourceId, start, end, excludeId,      │
│                   containerH, totalM) → boolean           │
└──────────────────────────────────────────────────────────┘
```

**依赖方向**（单向）：
```
overlapScanner ← useDragMove ← TimeCalendar → EventBar
  (纯函数)       (Hook)        (编排)       (渲染)
```

## 4. 数据流

### 4.1 mousemove 实时检测流

```
用户拖动鼠标
  ↓
useDragMove mousemove handler
  ↓ 计算预览位置 newStartMin / newEndMin / newResourceId
  ↓ 取目标列 DOM: querySelector('[data-resource-id="..."]')
  ↓
scanColumnOverlap()
  ↓ querySelectorAll('[data-event-bar]')
  ↓ 遍历每个 bar:
  │   ├─ dataset.eventId === excludeId → continue（自身跳过）
  │   ├─ dataset.isBackground === 'true' → continue（背景跳过）
  │   └─ barStart < newEnd && barEnd > newStart → hasOverlap=true
  ↓ 返回 boolean
  ↓
dragRef.isOverlapping = hasOverlap
  ↓ RAF → setDragState({ ..., isOverlapping })
  ↓
TimeCalendar 重渲染
  ↓ moveDragState.isOverlapping → EventBar prop
  ↓
EventBar 条件样式：
  ├─ isOverlapping=false → 蓝色半透明 + 白色虚线（正常）
  └─ isOverlapping=true  → 红色半透明 + 红色虚线 + 红框外发光（警告）
```

### 4.2 mouseup 写入/拒绝流

```
用户松手
  ↓
useDragMove mouseup handler
  ↓
dragRef.current.isOverlapping === true?
  ├─ YES → cleanup() + return（弹回，不调 onEventDrop）
  └─ NO  → onEventDrop({ type:'MOVE', ... }) → cleanup()
```

## 6. 状态管理

| 状态 | 类型 | 持有位置 | 传递方式 |
|------|------|----------|----------|
| `isOverlapping` | `boolean` | `dragRef.current.isOverlapping`（useDragMove 内） | ref → setDragState → moveDragState prop → TimeCalendar → EventBar prop |
| `moveDragState` | `{ eventId, resourceId, previewStartMin, previewEndMin, isOverlapping }` | `useDragMove` 内 useState | 返回值解构给 TimeCalendar |
| `excludeEventId` | `string` | `dragRef.current.eventId` | 传参给 scanColumnOverlap |
| `containerHeight` | `number` | `dragRef.current.containerHeight`（mousedown 时存储） | 传参给 scanColumnOverlap |
| `totalMinutes` | `number` | `dragRef.current.totalMinutes`（mousedown 时存储） | 传参给 scanColumnOverlap |

**isOverlapping 生命周期**：
```
mousedown → 无（dragState=null，不渲染 isOverlapping）
mousemove → 有（每帧更新，要么 true 要么 false）
mouseup   → 读最后值 → cleanup → 回到 null
```

## 7. 边界场景

| 场景 | 处理方式 |
|------|----------|
| 目标列无 bar（空列） | querySelectorAll 返回空 → 遍历跳过 → false → 正常放 |
| 目标列只有预览 ghost | ghost 的 eventId = excludeId → 跳过 → false → 正常放 |
| 目标列有背景事件 | data-is-background='true' → 跳过，不阻挡 |
| 拖拽同一列，原 bar 在预览位 | eventId 匹配 → 跳过 → 不跟自己比 |
| 拖拽到另一列，目标列有预览 ghost | eventId 匹配 → 跳过 |
| 容器 querySelector 返回 null | 静默 cleanup，弹回原位 |
| 页面滚动 | 拖拽期间页面不可滚动，用 mousedown 时存的 containerHeight |
| 窗口 resize | mousemove 每帧 getBoundingClientRect 实时量，自动适配 |
| 鼠标松开在窗口外 | 已有 mouseleave/blur 异常清理，状态不会卡死 |
| 多个 bar 紧密排列 | 逐个遍历，任一个重叠即返回 true |
| 拖拽到边界的 bar 上 | bar 占满区间 → hasOverlap=true → 红色+拒绝 |

## 9. 设计决策汇总

| 决策 | 结论 |
|------|------|
| 自身排除方式 | data-event-id + skip |
| 背景事件处理 | data-is-background + skip |
| 检测时机 | mousemove 实时 |
| 视觉反馈 | isOverlapping → 红色样式 |
| rect 计算 | 每次 mousemove 实时 getBoundingClientRect |
| containerHeight 来源 | mousedown 时存储（拖拽期不滚动） |
| 容器找不到 | 静默取消 |
| 模块拆分 | useDrag → 3 独立文件 + 新建 overlapScanner |
| 文件命名 | useDragMove.js / useDragResize.js / useDragCreate.js |

## 10. 已修复问题记录（防回退）

### 坐标系不匹配（发现 2 次）

**现象**：所有 DOM 扫描函数（`findNearestBar`、`scanColumnOverlap`）内部用 `pixelToMinutes(rect.top - cRect.top, ...)` 计算 bar 位置，结果是**容器相对偏移分钟**（范围 `[0, totalMinutes]`）。调用方（`useDragMove`、`useDragResize`）传的却是**绝对分钟**（从午夜 00:00 算起）。两者对不上 → 永远不重叠/不钳制。

| 受影响 | 修复 | 文件 |
|--------|------|------|
| 移动重叠检测 | `newStartMin - minMinutes`, `newEndMin - minMinutes` | `useDragMove.js:128` |
| 拉伸边界钳制 | `newStartMin - minMinutes` 入, `+ minMinutes` 出 | `useDragResize.js:119,124` |

**教训**：任何涉及 `pixelToMinutes(rect, ...)` 的地方，入参必须是偏移分钟。绝对分钟需先减 `minMinutes`。

### 文本选中残留（1 次）

**现象**：拖拽/拉伸时浏览器系统选中文字，视觉脏乱。

| 修复 | 文件 |
|------|------|
| `document.body.style.userSelect = 'none'` 在 mousedown 设置 | `useDragMove.js`, `useDragResize.js` |
| `document.body.style.userSelect = ''` 在全部 5 个清理路径恢复 | `useDragMove.js`, `useDragResize.js` |

**教训**：所有拖拽 Hook 的 `handleMouseDown` + 全部 cleanup 路径必须配 `userSelect`。

### 渲染性能（1 次）

**现象**：`container.getBoundingClientRect()` 写在 for 循环内，N 个 bar 调用 N 次。

| 修复 | 文件 |
|------|------|
| `var cRect = container.getBoundingClientRect()` 移到 for 之前 | `overlapScanner.js:4` |

### 行为不一致（1 次）

**现象**：`scanColumnOverlap` 跳过背景事件，`findNearestBar` 不跳过。拉伸和移动行为不对齐。

| 修复 | 文件 |
|------|------|
| `findNearestBar` 加 `if (bars[i].dataset.isBackground === 'true') continue` | `utils.js:33` |

### 死代码（1 次）

**现象**：`useDragCreate.js` 仍被 TimeCalendar import，但已被 `useBoxSelect` 替代。

| 修复 | 文件 |
|------|------|
| 移除 `import { useDragCreate }` | `TimeCalendar.jsx:9` |

### 重复 DOM 属性（1 次）

**现象**：`StaffColumn` 内部显式 `data-resource-id` + `{...restProps}` 再覆盖一次。

| 修复 | 文件 |
|------|------|
| 移除 StaffColumn 内部 L30-31 显式声明，统一由 TimeCalendar restProps 传入 | `StaffColumn.jsx:30-31` |

### 拒绝延迟（1 次）

**现象**：重叠拒绝后 `setTimeout 2000` 才清预览，红色幽灵停留 2s。

| 修复 | 文件 |
|------|------|
| 改立即清除（`setIsDragging(false)` 不等 setTimeout） | `useDragMove.js:162` |

### 松手弹回闪烁（2 次：move 已修、resize 再犯）

**现象**：松手后 `setIsResizing(false)` + `setResizeState(null)` 立即清预览 → 事件条弹回原位 → 数据刷新后才跳新位 → 闪烁。

**根因**：move 已用 `setTimeout(resizeRef=null 先，isResizing 后)` 模式修复过（第 1 次，设计文档 §11 决策5），但 resize 的 `handleMouseUp` 未同步（第 2 次）。两个 Hook 共享相同的松手清理模式，修复其中一个时必须检查另一个。

| 修复 | 文件 |
|------|------|
| 仅清 `resizeRef`，`isResizing`/`resizeState` 用 `setTimeout 2000` 延迟清 | `useDragResize.js:167-172` |

**教训**：`useDragMove` 和 `useDragResize` 共享 cleanup 模式（ref 先清 → state 延迟清）。任一方的 mouseup 改动，必须对照检查另一方。应抽取共享的 cleanup 工具函数消除此风险。

### 松手后样式延迟恢复（1 次）

**现象**：拉伸松手后 `resizeState` 保留 2s → EventBar 保持拖拽样式（虚线边框、半透明）→ 视觉延迟。

**根因**：TimeCalendar 用 `resizeState` 同时控制位置覆写和样式（`isResizing` prop）。拆分为两路：`hasPendingResize`（控制位置，含 `_final`）+ `isResizing`（控制样式，排除 `_final`）。

| 修复 | 文件 |
|------|------|
| mouseup 后 setResizeState 加 `_final:true`，立即 `setIsResizing(false)` | `useDragResize.js:173-184` |
| TimeCalendar 拆分 `hasPendingResize`（位置）和 `isResizing`（样式） | `TimeCalendar.jsx:290-306` |
