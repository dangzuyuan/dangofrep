## 1. 需求概述

### 业务背景
TimeCalendar 是一个纯展示层 React 时间轴视图组件，用于多列资源（员工/房间）的时间排程展示。支持主事件（可拖拽交互）和附属事件（只读背景）双层渲染。本组件从 `参考/timecalendar/timeline/` 复制至 `src/timeline/`，经最小化修改适配预约看板业务场景。

### 目标
- 纯 Props 驱动，不依赖任何业务 SDK（R1）
- 通过回调通知父组件用户操作，不在组件内部持久化
- 支持完整交互：点击、拖拽移动、拉伸调整、框选新建
- 适配本项目的 mdye 0.1.4 平台环境

### 范围
仅展示层的渲染和交互。数据处理、API 调用、状态持久化由业务层（App.jsx + hooks + loaders）负责。

### 修改原因

| 修改 | 原因 |
|------|------|
| 字体颜色 `ev.fontColor` | 原硬编码 `#fff`，无法满足后台配色配置 |
| 背景事件文字 | 原只渲染色块，需显示附属事件内容文字 |
| zIndex 调整 | 拖拽 div(z=3)覆盖文字(z=2)，click 穿透失效 |
| onClick→onMouseUp+dragMovedRef | onClick 被 useDragMove 的 preventDefault 阻止（HTML规范） |
| window.__openRecord | TimeCalendar props 传递 onClick 不可靠时兜底 |
| useDrag 3×preventDefault 移除 | 恢复浏览器 click 事件生成 |
| useDrag stopPropagation 移除 | React 合成事件中阻止 capture 阶段 handler |
| useDrag RAF 延迟 state | 避免 DOM 替换打断 click 生成 |
| useDrag 横向拖拽修复 | 跨列移动但时间不变时被误判为"无移动" |
| useDrag 松手不复位 | 避免弹回原位视觉效果（+2s超时兜底） |

## 4. 功能模块详细设计

### 4.1 TimeCalendar.jsx
- **职责**: 接收标准化 Props，渲染完整时间轴视图
- **Props**: 见 §5.1
- **核心计算**:
  - `timeMeta = useMemo` → `{totalMin = endMin-startMin, numSlots = ceil(totalMin/timejiange)}`
  - `calculatedRowHeight = numSlots × slotHeight`
  - `gridBg = repeating-linear-gradient(每 slotHeight-1px 一条横线)`
  - `getEventPosition(ev)` → `{top: %, height: %}` 按时间计算百分比
- **子组件渲染**: resources.map 为每列渲染 StaffColumn，内部 events.filter(resourceId===s.id) 为每列分配事件

### 4.2 EventBar.jsx（展示层核心，5处修改）
- **双模式渲染**: `if(isBackground)` 分支 → 只读/文字显示 | else → 全交互/拖拽手柄
- **拖拽交互**: TopHandle(onResizeStart:top) + DragDiv(onDragStart:move) + BottomHandle(onResizeStart:bottom)
- **点击检测（最终方案）**: onMouseUp + dragMovedRef(5px阈值)
  * `dragMovedRef = useRef(false)` — 首次渲染初始化
  * `useEffect` 注册 `document.addEventListener('mousemove')` — 任意移动设 dragMovedRef=true
  * DragDiv/TopHandle/BottomHandle 的 onMouseDown 中 `dragMovedRef.current = false`
  * `handleBarClick` 检查 dragMovedRef — false→点击、true→拖拽跳过
- **全局兜底**: `window.__openRecord(rowid)` — 当 onClick props 传递不可靠时直接调用（由 App.jsx useEffect 注册）

### 4.3 hooks/useDrag.js (782行，5处修改)
**useDragMove** — 拖拽移动：
- mousedown → `dragRef` 同步设置(起始位置/时间) → `requestAnimationFrame(setIsDragging(true))` (修改1) — 延迟避免DOM替换打断click
- 文档级 mousemove → pixelToMinutes → snapToGrid → 更新 dragRef + dragState
- 跨列检测: `moveEvent.target.closest('[data-resource-column]')` → dataset.resourceId
- 文档级 mouseup → 检查变化: `previewStartMin !== originalStartMin || newResourceId !== originalResourceId` (修改2：增加横向判断) → onEventDrop({type:'MOVE',...})
- 松手后仅清理 dragRef，不清理 isDragging/dragState（修改3：避免弹回 + 2s超时兜底）

**useDragResize** — 拉伸时长：
- 类似 useDragMove，但通过 direction(top/bottom) 决定修改 start 还是 end

**useDragCreate** — 框选新建：
- StaffColumn 的 onMouseDown 触发 → 记录起始时间 → mouseup 计算时间段 → onSelectSlot

**全部修改（5处）**：
1. 3处 `e.preventDefault()` 移除（恢复 click 生成）
2. useDragMove `e.stopPropagation()` 移除（React 合成事件兼容）
3. useDragMove `setIsDragging(true)` 包裹在 RAF 中
4. useDragMove 横向拖拽增加 resourceId 判断
5. useDragMove 松手不立即复位拖拽状态

## 6. 数据流设计

### 6.1 数据流向

```
业务层(App.jsx) → adaptTableViewData → TimeCalendar Props
  resources: [{id, accountId, name, departmentId, departmentName}]
  events: [{id, resourceId, startTime, endTime, title, color, fontColor, isBackground}]
  departmentTree: [{id, name, children}]
    ↓
TimeCalendar 内部
  departmentTree → TableHeader 渲染表头
  events + resources → staffEvents 过滤 → EventBar 渲染
    ↓ 用户交互
  useDragMove/DragResize/DragCreate → 回调 → 业务层
```

### 6.2 事件匹配逻辑

```javascript
resources.map((s, idx) => {
  const staffEvents = events.filter(
    ev => ev.resourceId === s.id || ev.resourceId === s.accountId
  );
  // staffEvents 为该列要渲染的事件列表
  // 按重叠布局算法(本版本由组件内部处理, R9)计算 left/width
})
```

### 6.3 点击交互流程（实际实现）

```
用户点击事件条
  → DragDiv onMouseDown → dragMovedRef=false (同步ref) → onDragStart(useDragMove)
  → useDragMove.handleMouseDown:
    · 无 preventDefault (已移除)
    · 无 stopPropagation (已移除)
    · dragRef 同步设置
    · RAF 延迟 setIsDragging(true) (避免 DOM 替换)
  → 用户松手(无移动)
  → document.mouseup → useDragMove.handleMouseUp:
    · previewStartMin===originalStartMin && newResourceId===originalResourceId
    · → 无变化 → dragRef=null → 返回（不调 onEventDrop）
  → mouseup 冒泡到 Bar → onMouseUp → handleBarClick
    · dragMovedRef=false (无移动) → 点击!
    · → onClick(ev) → TimeCalendar → onEventClick(ev)
    · → dragHandler.onEventClick → utils.openRecordInfo({rowid})
    · → 兜底: window.__openRecord(rowid)
```

### 6.4 拖拽流程

```
拖拽(有移动):
  → mousemove → dragMovedRef=true → 更新 dragRef.previewStart/EndMin
  → mouseup → onEventDrop({type:'MOVE', eventId, oldResourceId, newResourceId, newStart, newEnd})
  → 松手后: dragRef=null, isDragging/dragState 保持(不立即复位) + 2s 超时清理
  → 业务层处理写入 → onSaved → refreshKey → 数据重载 → 重新渲染
  → 重渲染时 isDragging 仍为 true，但事件数据已更新，位置正确
  → 2s 后超时清理 isDragging + dragState
```

## 10. 边界场景 & 异常处理

| 场景 | 处理 |
|------|------|
| **空 resources** | 显示"暂无人员数据"（大图标+文字，居中） |
| **空 events** | 每列显示"暂无安排" |
| **事件超出时间范围** | `height>0 && top<100` 检查，超出不渲染 |
| **拖拽越界** | 自动钳位到 begintime~endtime 内 |
| **拖拽取消(无移动)** | handleMouseUp 中 previewStartMin===originalStartMin → 不调 onEventDrop，清理拖拽状态 |
| **窗口失焦** | useDragCreate 强制清理框选状态 |
| **RAF 空值守卫** | 所有 RAF 回调中 `if(!dragRef.current)return` 防清理后执行 |
| **背景事件点击** | isBackground=true → pointerEvents:none，完全不响应 |
| **dragMovedRef 误判** | 5px 阈值过滤轻微抖动；任意移动即标记为拖拽 |
| **isDragging 未清理** | 2s 超时自动清理 (`setTimeout(setIsDragging(false), 2000)`) |

## 11. 关键设计决策（ADR）

### 决策1: onMouseUp 替代 onClick
- **原因**: onClick 依赖浏览器生成 click 事件，但 useDragMove 的原始 preventDefault 阻止 click 生成
- **备选**: 继续修复 onClick 链（移除所有 preventDefault + stopPropagation + RAF + 各种补丁）
- **选择理由**: onMouseUp 在 click 之前触发，不依赖浏览器 click 生成，配合 dragMovedRef 可靠区分点击/拖拽

### 决策2: dragMovedRef 5px 阈值
- **原因**: 需要区分"鼠标轻微抖动"和"真实拖拽"
- **阈值**: 5px（与 react-beautiful-dnd 一致）
- **实现**: document 级 mousemove 监听，任意轴超过 5px 即标记

### 决策3: window.__openRecord 全局兜底
- **原因**: TimeCalendar→onClick→Arrow Function→onEventClick 链在 React 合成事件+useDrag 拦截下不稳定
- **实现**: App.jsx useEffect 一次性注册 `window.__openRecord(rowid)`, EventBar 直接调用
- **风险**: 全局命名空间污染 → 已用 `__openRecord` 前缀 + useEffect 清理

### 决策4: zIndex 调整（3→1, 2→5）
- **原因**: 原拖拽 div(z=3)覆盖文字(z=2), click 穿透失效 → 事件被拖拽区拦截
- **修复**: drag div→1, text span→5, text 有 pointerEvents:none 穿透到拖拽区
- **参考**: beta1 EventBar 的 Z_BAR_TITLE > Z_DRAG_MOVE_HANDLE 模式

### 决策5: 乐观更新 + 松手不复位
- **原因**: isDragging 清除→事件条弹回原位→useAutoRefresh 刷新→跳新位→视觉闪烁
- **修复**: dragHandler.onEventDrop 在 API 前修改 events 数组(start/dur/accountId); useDragMove 松手不立即复位 isDragging
- **兜底**: 2s 超时强制清理
