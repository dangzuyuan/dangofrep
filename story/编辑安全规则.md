# 编辑安全规则

**创建日期**: 2026-05-30  
**原因**: 清调试日志时误删了关键业务代码，导致数据无法加载

---

## 事故还原

清日志时用 `edit` 工具匹配了一段包含 `useEffect` + `return` 的代码块。由于 `oldString` 匹配范围过大，删除了 `useEffect` 之后、`return` 之前的所有中间代码（useDataLoader / adaptTableViewData / allStaffCount / handleRefresh）。

## 根因

1. `edit(oldString)` 的 `oldString` 跨度过大，包含了不相干的结构边界
2. 编辑前未重新读取文件确认当前状态
3. 编辑后未立即验证修改结果

---

## 5条铁律

### 1. 编辑前必读文件

每次 `edit` 前，如果距离上次 `read` 这个文件超过了 **2次对话轮次**，必须先重新 `read` 确认当前内容。

### 2. oldString 精准匹配

```
❌ 错误: "  useEffect(function() {\n    ...\n  }, []);\n\n  return ("
    → 跨度过大，误删中间所有代码

✅ 正确: 只匹配要删除的精确内容行，前后各留1行作为定位锚
```

### 3. 一编辑一验证

每次 `edit` 后，立即对修改区域做一次 `read`（offset 定位到修改行前后 10 行），确认：
- 要删的已删
- 要留的还在
- 没有多删/少删

### 4. 批量操作用 bash

复制/移动/删除文件用 `bash` 工具（Copy-Item / Remove-Item），不用 `edit`。`edit` 仅用于修改文件**内容**。

### 5. 调试日志按行添加/删除

```
添加诊断时:
  → 一行一个 console.log，确保 oldString 能精确匹配这一行

删除诊断时:
  → 逐行删除，每行单独一次 edit
  → 或使用 replaceAll 替换 console.log("【诊断... 为空串（危险，需验证）
```

## TimeCalendar 展示层修改规则（最高优先级）

**前提**：原则上不修改展示层（R1），仅当业务需求无法通过外部传参满足时，才以最小化方式修改。

### 修改前

1. **备份原文件**：`cp 原文件.jsx 原文件.jsx.bak-YYYYMMDD`
2. **确认修改范围**：只改必须改的代码行，不动其他任何逻辑
3. **列出影响**：明确哪些功能会受影响（即使理论上不影响）

### 修改时

4. **每处修改加注释**：`/* [修改记录 YYYY-MM-DD] 原因：xxx */`
5. **只加代码、不改结构**：新增代码行，不删除/移动原有代码
6. **一次只改一个文件的一个功能点**

### 修改后

7. **更新 `src/timeline/修改记录.md`**：记录文件、行号、原因、影响
8. **更新组件调用规则**：如修改了 Props 或行为，同步更新 `参考/TimeCalendar组件调用规则.md`
9. **MD5 验证**：确认只有目标文件被修改，其他展示层文件不变
10. **功能验证**：确认原有功能不受影响

### 铁律 8: 编辑前后验证变量引用完整

**背景**：编辑删除代码行时，可能同时删除了后续代码依赖的变量声明，导致运行时 ReferenceError。

### 必须遵守的检查

```
❌ 错误:
  编辑: 删除 "const startMin = Math.min(...)" 和 "const endMin = Math.max(...)"
  结果: 后面 RAF 闭包中 startMin/endMin 变成 undefined → 运行时崩溃

✅ 正确:
  1. 编辑前，grep 确认要删除的行中变量名在文件中还有哪些引用
  2. 如果后续代码引用了这些变量，必须先添加新声明再删除旧的
  3. 编辑后，read 上下 10 行确认所有引用的变量都存在
```

### 通用模式

```
编辑前:
  grep "变量名" 目标文件  → 确认所有引用位置
  保留需要的引用 → 在旧声明和新声明之间加桥接代码
编辑后:
  read 修改区域 → 逐行验证变量引用链完整
```

### 本周实际事故

| 文件 | 编辑内容 | 后果 |
|------|----------|------|
| useDrag.js | 删除 `const startMin/endMin` 行（以为不需要） | RAF 闭包引用 `startMin`→ReferenceError |
| useDrag.js | 使用 `timeToMin(begintime)` 但文件未 import | 运行时 Script error |

### 自动化检查

编辑后立即执行：
```bash
rg "变量名" 目标文件  # 确认声明存在
rg "from|import" 目标文件  # 确认导入覆盖所有外部函数
```

- [ ] **edit 后立即 read 改动的上下 10 行验证**

## 铁律 7: 先读后写——禁止在判断条件前修改变量

```
❌ 错误:
  ev.accountId = newValue;           ← 先改了
  if (newValue !== ev.accountId) {}  ← 再判断 → 永远 false

✅ 正确:
  var oldVal = ev.accountId;         ← 先保存旧值
  ev.accountId = newValue;           ← 再修改
  if (newValue !== oldVal) {}        ← 用旧值判断
```

使用 `useEffect`/`useState`/`useRef`/`useCallback`/`useMemo` 等 React Hook 后，**必须**：
1. `grep` 文件头确认 `import React, { ..., useEffect }` 包含该 Hook
2. 如果未包含，先 edit import 行添加，再写其他代码

- [ ] 修改区域上下 10 行已读，确认无副作用
- [ ] 变量引用完整（如 `loading`、`handleRefresh` 在使用处有定义）
- [ ] 没有多出的空行/缺失的括号
- [ ] 如果删除了代码块，确认块内的变量在其他地方不再被引用
