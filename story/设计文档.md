## 1. 需求概述

### 业务背景
明道云预约时间看板视图插件已开发完成，拥有完整业务逻辑与成熟取数流程。但现有代码中业务逻辑与展示层耦合，导致：
- 工具函数多处重复（helpers.js 与 parseParam/parseField/mdyeApi 共 14 处重复）
- 数据层和 UI 层无法独立测试和替换
- env 参数解析、字段类型处理等反复踩坑
- mdye SDK 从 0.0.20 升级至 0.1.4，写入 API 路径和格式均发生变化

### 目标
1. 将数据取数/业务逻辑层与 TimeCalendar 展示层彻底隔离，两层独立运行
2. 消除工具函数重复，建立唯一函数源
3. 封装万能字段解析/写入函数（覆盖 40+ 字段类型）
4. 适配 mdye 0.1.4 平台 API 和运行环境
5. 保持原有业务逻辑、页面 UI、交互效果完全不变

### 范围
仅做架构分层重构、代码去重整合、函数封装，不新增或删减任何业务功能。

## 2. 现状分析

### 现有问题
- **代码重复**：helpers.js 与 parseParam.js/parseField.js/mdyeApi.js 三文件间 14 个函数完全重复，COLOR_PALETTE 常量三处定义
- **耦合严重**：beta2 的 App.jsx 直接渲染 TimeCalendar，业务逻辑(hooks/loaders)和 UI 代码(timeline/)混在同一项目却未做清晰的接口分离
- **API 版本不兼容**：beta2 基于 mdye 0.0.20（`apis.worksheet.editWorksheetRows`），本项目使用 0.1.4（`api.updateWorksheetRow`），路径、函数名、参数格式均不同
- **TimeCalendar 组件 click 失效**：新版 TimeCalendar（参考/）的 useDrag.js 在 mousedown 时调用 `e.preventDefault()`，按 HTML 规范阻止了 click 事件生成
- **colIdx 残留**：loaders 输出中携带列索引，但在解耦架构下应由 TimeCalendar 按 resourceId 自行匹配列位置
- **11 个 beta2 过期文件**：BookingBar/ScheduleBar/operateLoader 等旧版代码仍存在于源码目录

### 技术债务
- helpers.js（149行）：与三工具文件完全重复，已被删除
- utils.js（254行旧版）：extractTime/safeParseJson 等函数已被覆盖，已删除
- 旧版 EventBar/TableHeader/TimelineAxis 根目录文件：与 timeline/ 内同名不同内容

### 改造原因
适配 mdye 0.1.4 平台、建立可持续维护的架构、降低后续开发成本。

## 4. 功能模块详细设计

### 4.1 App.jsx (213行)
- **职责**：主应用入口，env 参数默认值、时间轴配置、响应式布局、组件组装、回调分发、Error Boundary 异常兜底
- **输入**：`env` (mdye 环境变量)、`config` (mdye 配置)、`apis/utils/api` (mdye SDK)
- **输出**：React 元素树 (ErrorBoundary → AppWrap → Toolbar + TimeCalendar + DebugPanel)
- **依赖**：useDataLoader, useAutoRefresh, adaptTableViewData, createDragHandler, parseParam, constants, Toolbar, DebugPanel, TimeCalendar

### 4.2 useDataLoader.js (120行)
- **职责**：三链数据加载编排器
- **输入**：`currentDate: string`, `refreshKey: number`
- **输出**：`{staffMap, events, loading, logs, setLogs, controlsRef, isSilentReload}`
- **加载顺序**：header(链1) → sub(链2) → main(链3)，每条链独立 try/catch
- **加载锁**：`loadingRef = {header:false, main:false, sub:false}` 防并发
- **静默刷新**：`isSilentReload=true` 时不设 `loading=true`
- **合并逻辑**：`finalStaffMap = new Map([...headerStaffMap, ...mainStaffMap])`, `finalEvents = [...mainEvents, ...subEvents]`

### 4.3 useAutoRefresh.js (24行)
- **职责**：监听 md_emitter 的 new-record/delete-record/update-record 事件
- **输入**：`isSilentReloadRef: Ref<boolean>`, `setRefreshKey: (k=>k+1)=>void`
- **输出**：无返回值（副作用：更新 ref 和 state）
- **注册**：`md_emitter.addListener` 在 useEffect 中注册，组件卸载时 removeListener

### 4.4 headerLoader.js (85行)
- **职责**：加载表头人员列表（链1）
- **输入**：`(headerDisplayParam, headerGroupParam, headerFilterParam, headerConditionValue: string, logArr: string[])`
- **输出**：`{staffMap: Map<accountId, {accountId, rowid, name, departmentId, departmentName}>, logs: string[]}`
- **流程**：resolveWorksheet → getRelationOpenView → getViews → getControls → getFilteredRows(全量) → 如有过滤器 → filterByFieldText → parseField → 去重 → 按部门拼音+姓名拼音排序 → 重建有序 Map

### 4.5 subEventLoader.js (81行)
- **职责**：加载当天附属事件（链2）
- **输入**：`(subDateParam, subBeginParam, subEndParam, subDurParam, subHeaderParam, subDisplayParam, subBgParam, subFontParam, staffMap, currentDate, logArr)`
- **输出**：`{events: R5Event[], logs: string[]}`
- **前置检查**：`subDateParam && subBeginParam` 都为空 → 跳过整条链
- **匹配优先级**：`subHeaderParam`(关联字段选择器) > `subDisplayParam` → name 模糊回退
- **输出格式**：R5 中间格式，type:"sub"，无 colIdx

### 4.6 mainEventLoader.js (87行)
- **职责**：加载当天主事件（链3）
- **输入**：`(mainDateParam, mainBeginParam, mainEndParam, mainDurParam, mainHeaderParam, mainDisplayParam, mainBgParam, mainFontParam, headerStaffMap, currentDate, logArr)`
- **输出**：`{events: R5Event[], mainStaffMap: Map, controls: Array, logs: string[]}`
- **特殊处理**：wsId=config.worksheetId, vId=config.viewId, 合并 config.filters.filterControls
- **匹配优先级**：`mainHeaderParam`(关联字段选择器, optFieldId来源) > `mainDisplayParam` → name 模糊回退
- **新人处理**：未匹配到但 accountId 非空 → 加入 mainStaffMap（departmentName="未分组"）
- **标题提取**：`extractFieldText(rec[displayFieldId], control)` — 万能解析，覆盖所有字段类型
- **输出格式**：R5 中间格式，type:"main"，无 colIdx

### 4.7 adapters.js (77行, 4导出)
- **职责**：数据翻译层，将 R5 中间格式转为 TimeCalendar 标准 Props
- **adaptResources**(staffMap: Map) → Resource[]：Map.forEach → `{id=accountId, rowid, accountId, name, departmentId, departmentName}`
- **adaptEvents**(rawEvents: R5Event[]) → Event[]：过滤空 start → startTime 统一补 ":00" → dur 计算 endTime → fc→fontColor → type→isBackground
- **buildDepartmentTree**(resources: Resource[]) → Department[]：按 departmentId 分组 → 部门按 departmentName 拼音排序 → 部门内按 accountId 排序
- **adaptTableViewData**(staffMap, events) → {resources, events, departmentTree}：串联调用上述三个函数

### 4.8 dragHandler.js (195行, 1导出)
- **职责**：TimeCalendar 回调 → mdye 0.1.4 API 翻译器
- **createDragHandler(opts)** → `{onEventClick, onEventDrop, onEventResize, onSelectSlot, onEventDelete}`
- **opts**：`{api, apis, utils, config, operatorFieldId, beginFieldId, durationFieldId, dateFieldId, statusFieldId, events, onSaved, controlsRef, staffIdMap}`
- **operatorFieldId 来源**：`mainEventHeaderField.fids[0]` (优先) > `mainEventDisplayContent.fids[0]` (兜底)
- **写入 API**：更新 `api.updateWorksheetRow({newOldControl})`、新增 `api.addWorksheetRow({receiveControls})`、删除 `api.deleteWorksheetRow({rowIds})`
- **乐观更新**：`ev.start/dur/accountId` 在 API 调用前修改，避免视觉弹回
- **字段类型常量化**：`type: CONTROL_TYPE_DATETIME/NUMBER/RELATION/DATE` 替代魔法数字 16/6/29/15

## 6. 数据流设计

### 6.1 初始化数据流
```
env (mdye)→ App.jsx → useDataLoader(currentDate, refreshKey=0)
  → 解析31个env参数 → 三链并行加载
    → 链1 headerLoader: resolveWorksheet→getFilteredRows(全量)→parseField→staffMap
    → 链2 subEventLoader: resolveWorksheet→buildDateFilter→getFilteredRows(当天)→subEvents
    → 链3 mainEventLoader: config.worksheetId→buildDateFilter+config.filters→getFilteredRows(当天)→mainEvents
  → 合并: finalStaffMap=header∪main, finalEvents=main+sub
→ adaptTableViewData(staffMap, events)
  → adaptResources→resources[]
  → adaptEvents→events[] (HH:mm→HH:mm:ss, fc→fontColor, type→isBackground)
  → buildDepartmentTree→departmentTree[]
→ <TimeCalendar resources events departmentTree .../>
→ useAutoRefresh注册md_emitter监听
```

### 6.2 拖拽写入数据流
```
用户拖拽→ TimeCalendar useDragMove 处理DOM
  → mouseup→ onEventDrop({type:'MOVE',eventId,newResourceId,newStart,newEnd})
  → App.jsx→ dragHandler.onEventDrop:
     1. 计算duration
     2. events.find((e.rowid||e.id)===eventId) → 原始event
     3. 乐观更新 ev.start/ev.dur/ev.accountId
     4. 构造 newOldControl[{controlId,type,value}] (buildFieldValue)
     5. api.updateWorksheetRow({appId,worksheetId,rowId,newOldControl})
     6. .then → onSaved → isSilentReload+refreshKey++ → useDataLoader重载 → 重新渲染
```

### 6.3 点击数据流
```
点击事件条→ mousedown→ dragMovedRef=false→ onDragStart(useDragMove)
  → mouseup (无移动)→ handleBarClick检测dragMovedRef=false
  → onClick(ev)→ TimeCalendar→ onEventClick(ev)
  → dragHandler.onEventClick→ utils.openRecordInfo({rowid})
  → 兜底: window.__openRecord(rowid) (全局函数注册于App.jsx useEffect)
```

### 6.4 自动刷新数据流
```
外部变更: md_emitter.fire('new-record'|'delete-record'|'update-record')
  → useAutoRefresh 捕获 → isSilentReload=true → refreshKey++
  → useDataLoader 重载 → adaptTableViewData → TimeCalendar 更新

插件内操作: dragHandler.onSaved → handleRefresh
  → 同上路径
```

### 6.5 框选新建数据流（useBoxSelect.js）

```
用户 mousedown 空白列 → handleSelectStart (useBoxSelect)
  → 跳过 data-event-bar → 记录 snapped 起点
  → setIsSelecting(true) → 虚线蓝框渲染
  → document.body.style.userSelect='none' (防文字选中)

用户拖动 (mousemove):
  → pixelToMinutes → [0, totalMinutes] 钳制（修复 1）
  → 双向扩展: Math.min/max(起点, 当前位置)
  → 遇 data-event-bar → 停止扩展（return）
  → requestAnimationFrame 更新 selectState → 蓝框实时变化

用户松手 (mouseup):
  → snapToGrid(startMin, endMin) → 绝对时间转换（修复 2）
  → <1 格 → 清理不创建（防误触）
  → mouseup 在事件条上 → 清理不创建
  → ≥1 格 → onSelectSlot → dragHandler.onSelectSlot
    → 组装 controls: 员工(buildFieldValue 29) + 开始时间(type 46/16) + 日期(type 15) + 时长(type 6) + 结束时间(type 46/16, 兜底)
    → 遍历 controlsRef 自动填充所有带默认值的字段（extractRowid/getDefaultValue/buildFieldValue 三轮）
    → api.addWorksheetRow → onSaved + utils.openRecordInfo

ESC 键取消: document.addEventListener('keydown', escHandler) → cleanup()
窗口失焦/隐藏: 自动清理 box select 状态
```

### 6.6 拖拽拉伸数据流

```
拖拽移动 (onEventDrop):
  useDragMove → mouseup → onEventDrop({type:'MOVE',eventId,oldResourceId,newResourceId,newStart,newEnd})
  → dragHandler.onEventDrop:
    1. 乐观更新 events 数组(start/dur/accountId)
    2. 构造 newOldControl[{controlId, type, value}]
    3. api.updateWorksheetRow → onSaved → 刷新

拉伸调整 (onEventResize):
  useDragResize → mouseup → onEventResize({type:'RESIZE',eventId,newStart,newEnd})
  → dragHandler.onEventResize:
    1. 乐观更新 events 数组(start/dur)
    2. 构造 newOldControl[{beginFieldId, durationFieldId}]
    3. api.updateWorksheetRow → onSaved → 刷新
```

## 7. 接口定义

### 7.1 R5 中间格式
**staffMap**：
```typescript
Map<accountId: string, {
  accountId: string        // parseField.id || text (主体标识)
  rowid: string            // 记录自身rowid (用于 API 写入)
  name: string             // parseField.text (显示名称)
  departmentId: string     // 分组ID
  departmentName: string   // 分组名 (无分组="未分组")
}>
```

**events** (无 colIdx)：
```typescript
Array<{
  rowid: string            // 明道云记录ID (编辑/删除回写)
  accountId: string        // 对应表头主体ID
  start: string            // "HH:mm"
  dur: number              // 分钟数
  title: string            // extractFieldText 结果
  color: string            // 背景色 hex (safeColor)
  fc: string               // 字体色 hex (safeColor)
```

## 10. 边界场景 & 异常处理

### 10.1 数据边界
| 场景 | 处理 |
|------|------|
| 无表头 | staffMap为空→resources=[]→TimeCalendar显示"暂无人员数据" |
| 无主事件 | events=[]→每列显示"暂无安排"→Toolbar计数为0 |

| 参数缺省 | App.jsx常量兜底(beginTime→"08:00", timeInterval→15) |

### 10.2 运行时
| 场景 | 处理 |
|------|------|
| 链加载失败 | 独立try/catch，只记addLog，不阻断其他链 |
| 加载锁 | loadingRef防React StrictMode并发调用 |
| 静默刷新 | isSilentReload=true→不显loading |
| cookie过期 | mdyeApi异常→loaders catch→addLog记录 |
| 时长/时间缺失 | extractTime返回null→记录跳过 |
| 附属无匹配主体 | name模糊回退→仍未匹配→su++跳过 |
| 主事件新人 | 动态加入mainStaffMap→部门="未分组" |
| 拖拽API失败 | .catch(console.error)→界面不刷新 |
| 点击vs拖拽 | dragMovedRef+5px阈值→拖拽时不触发点击 |
| 窗口resize | App.jsx监听→重新计算colWidth→响应式 |

## 11. 关键设计决策（ADR）

### 决策1: 解耦边界 = src/timeline/ 目录
- **原因**: 展示层不依赖mdye SDK，可独立测试和替换
- **备选**: 不设目录边界，靠代码规范约束
- **选择理由**: 目录边界可grep自动验证，比规范约束更可靠

### 决策2: 三文件工具函数不合并
- **原因**: parseParam/parseField/mdyeApi 三者职责边界清晰(参数解析/字段提取/API调用)
- **备选**: 合并为一个 monolithic 工具文件
- **选择理由**: 单一职责、可独立测试、与 STANDARD.md 文档结构一致

### 决策3: adapters 独立翻译层
- **原因**: loaders输出mdye格式，TimeCalendar需要标准格式，中间需翻译
- **备选**: loaders 直接输出 TimeCalendar 格式
- **选择理由**: loaders 换展示组件时只改 adapters 不动 loaders；adapters 仅做格式转换不做业务校验(R4)

### 决策4: window.__openRecord 全局兜底
- **原因**: TimeCalendar props传递 onClick 在 React 合成事件+useDragMove 拦截下不可靠
- **备选**: 继续修复 onClick 链
- **选择理由**: onClick 链涉及多层(EventBar→TimeCalendar→App)，修复成本高且不稳定；全局函数一次注册、永久可靠

### 决策5: buildDepartmentTree 排序键修复
- **原因**: 原按 departmentId(UUID)排序与 headerLoader 按 departmentName(拼音)不一致，多部门下列体错位
- **修复**: 1行改动 `a.id.localeCompare(b.id)`→`a.name.localeCompare(b.name,"zh")`
- **教训**: 多模块各自排序必须用同一键

### 决策6: 乐观更新消除拖拽弹回
- **原因**: isDragging清除后事件条弹回原位→useAutoRefresh刷新后跳新位→视觉闪烁
- **修复**: dragHandler.onEventDrop 在 API 调用前修改 events 数组元素(start/dur/accountId)
- **风险**: API 失败时本地状态和服务端不一致→下次刷新时恢复
